# ZCode Pet（原生预览版）

独立 C++ Win32 桌宠，直接只读观察已经运行的官方 ZCode，无需修改安装包、源码、配置或启用调试端口，也不启动新 agent。

## Spine 预览版（0.2.0）

[下载发布包](https://github.com/Nakiha/Zcode-Pet/releases) · [GIF / GPU 优化版 0.1.0](https://github.com/Nakiha/Zcode-Pet/releases/tag/v0.1.0)

默认加载用户提供的 Spine 4.2.43 导出，使用固定版本的官方 spine-cpp 4.2（完整上游来源见 `third_party/spine-cpp/UPSTREAM.txt`）。通过 AnimationState 混合衔接动作，默认 0.22 秒；不把 Spine 转成 GIF 播放。工具栏“宠物大小”页可以切换 Spine/GIF，选择保存；Spine 资源不可用时回退 GIF。启动参数 `--gif` 仅本次强制使用原始 GIF。

| 状态 | Spine 动画 |
|---|---|
| 空闲 | a |
| 工作中 | d |
| 等待回答 / 空闲悬停 | e |
| 新完成动作 | c |
| 错误、中断、拖动 | b |

映射、混合时间和角色帧率可在 `assets/spine/animations.ini` 调整，重启生效。角色正常按素材节奏以 30 FPS 更新，切换混合期间 60 FPS；界面加载弧线、扫光和浮层交互独立跟随显示器刷新率。默认角色使用小画布软件三角形渲染及双线性采样，避免每秒额外向 GPU 提交角色帧；不改变骨骼、网格、裁剪、颜色混合或动作衔接。保留 `--spine-gpu` 原生 D3D11 后端作对照，它与面板共用设备，不引入 SDL/SFML/游戏引擎。

本机默认 224 px 角色的同轮对照：仅角色时 GIF/Spine 的应用 GPU 3D 均接近 0%，CPU 约 0.36%/0.40%；含三个工作会话时 GIF GPU 约 0.066%，Spine 两轮约 0.082%/0.067%，CPU 约 0.44%/0.38%。这些是此机器的整体进程计数，不代表整卡功耗；该轮桌面流媒体采集已停止，DWM 计数没有可用于归因的数据。直接 GPU 角色路径在该小尺寸下约 0.9%～1.5%，故未作为默认。九个动画的 512 px 软件/硬件参考图预乘通道平均差异均低于 0.1/255，无单像素差异超过 8/255。

## 运行

解压便携包，双击 `ZCodePet.exe`。保持 `assets` 文件夹与 EXE 同目录。

- 悬停宠物：展开紧凑会话面板；鼠标可移进面板交互，离开两者 260 ms 后自动收起；勾选右键“固定会话面板”后保持显示。固定选择会随设置保存并在重启后恢复。Esc 或手动收起会取消固定。面板基础宽 312 DIP，默认额外放大到 115%，最多同时显示 3 行，每行基础高度 34 DIP，高度随会话数缩短。仅显示铺满面板的会话行，没有顶部标题、关闭按钮或底部计数，也没有外层 padding、独立卡片背景和卡片间隙；会话间用较明显的灰紫分隔线区分，分隔线两端各保留 10 DIP 行内边距。左侧为会话标题，右侧先显示加大加粗的状态持续时间，再显示低饱和浅色实心、深色文字的胶囊。胶囊贴右锚定，时间长度变化不会推动它；按实际文字宽度分配空间，标题占据全部剩余宽度后才省略。状态灯采用半径 7.5 DIP 的单层实心圆，移除淡色外圈：薄荷绿勾为完成，雾蓝圆底内的旋转弧线为工作中，玫瑰粉叉为错误，杏橙叹号为等待回答，薰衣草紫短横为中断，中性灰点为状态未知，蓝灰空心圈为离线，不闪烁。工作中弧线约 1.2 秒旋转一周，限制在现有圆底内，不增加外圈。运行中的标题有约 2.8 秒一轮的蓝紫扫光：56 DIP 宽的清晰字形亮带，中心提高为明亮的银灰紫色，不叠加字形外的模糊柔光，裁剪在标题区域内，不覆盖时间或状态标签。
- 拖动宠物：移动，已展开的会话面板持续跟随，不会因开始拖动而收起。拖拽定位先限制在显示器工作区内，动画刷新不再同时修正位置，避免触边时来回拉扯闪烁，向屏幕内拖回立即响应；滚轮：只缩放宠物。默认宠物为 128 DIP。右键可分别调节宠物大小和面板缩放，也可恢复默认，偏好保存在 `%LOCALAPPDATA%/ZCodePet/settings.ini`。
- 面板滚轮：浏览最近最多 40 个未归档会话；Esc 收起。不抢焦点。
- 点击会话行或完成/等待提醒正文：用 Windows 原生 UI Automation 在 ZCode 侧栏定位项目及完整标题，打开唯一匹配的已有会话。提醒正文跳转后仍保留，叉号只关闭提醒。后台不导航、不发送消息或创建任务；UIA 在独立线程运行，不阻塞动画。找不到、重名、折叠、被筛选或无法聚焦时显示托盘提示，需先在 ZCode 中展开对应项目并让条目可见。当前 AX 未暴露 session ID，故不能保证所有会话均可跳转；不使用模糊匹配或固定坐标猜选。多窗口重复显示同一会话时也拒绝歧义候选。
- 宠物整个窗口矩形（包括 GIF 透明角落）均可悬停、拖动、滚轮及右键。透明像素保留最低非零 alpha 1/255，避免 Windows 分层窗口逐帧穿透，视觉不添加背景框。
- Session 行和提醒正文都有浅紫色 hover / press 反馈，文字、徽章及布局保持固定。反馈层直接铺满整行或整个提醒表面，移除内缩 padding 和行内小圆角，只由窗口最外层的原生圆角裁剪；内容文字、徽章的留白保持原样。行 hover/press 为 16%/30%、提醒为 14%/28%，工具栏背景及选中图标颜色也平滑过渡。原有面板边框在反馈层后绘制。统一使用 CSS ease-out，悬停约 140 ms 渐入、160 ms 渐出，按下 40 ms、抬起 120 ms；短按反馈从按下起至少保留 85 ms，点击动作仍立即执行，移出则取消保留。中途反向从当前颜色继续。交互过渡接入同一个垂直同步时钟，跟随显示器刷新率，结束后提交归位帧并停止高频刷新，不增加固定 60 Hz 定时器。按下拖出不触发导航，关闭按钮仍独立处理。
- 右键宠物或面板：打开图标主导的横向亚克力工具栏，悬停或键盘聚焦时显示说明。尺寸和文字设置在同一横条切换子页；固定/字体模式有选中态。支持方向键、Tab、Enter/Space，Esc、失焦或点击外部关闭。保留尺寸、恢复默认、素材来源和退出功能。
- 托盘图标也能打开面板或退出。关闭面板不会退出宠物。
- EXE、窗口与托盘使用内嵌的紫色爪印状态图标，提供 16/20/24/32/40/48/64/256 像素尺寸。托盘跟随窗口 DPI 选取图标，支持现代通知区回调；Explorer 重启后接收 TaskbarCreated 并重新注册，不依赖外部 ico 路径。probe 的 trayRegistered、trayIconLoaded、trayVersion4 可检查注册与资源加载。
- 工具栏“背景材质”提供实时亚克力（模糊后方窗口）、壁纸云母 Mica（仅取桌面壁纸形成背景，不透出后方窗口）、纯色。选择立即应用于 Sessions、所有提醒及工具栏，并保存到现有 settings.ini；原用户默认仍保持亚克力。材质受 Windows 透明效果、主题及可用性策略控制，不可用时使用浅色实底。
- 会话和提醒默认以宠物水平中心为锚点，初始位置为整组浮层留出居中空间；靠近屏幕边缘时仍优先保证可见。会话、提醒和工具栏统一使用按系统 DPI 缩放的 16 DIP 最小屏幕边距。各浮层共用避让算法：会话避开宠物，提醒避开会话和宠物，工具栏避开全部可见窗口，并为提醒的外伸关闭钮预留空间。上下放不下时尝试左右空位，尺寸/行数/工具栏子页变化后重新定位；空间极小时选择交叠最小的位置。

界面使用与宠物粉发、紫色缎带协调的奶白樱粉到淡紫渐变，在系统亚克力上叠加 50–56% 的乳白浅色着色层，保留背景的模糊与明暗变化，同时避免深色壁纸使文字对比不足。会话面板、独立提醒与右键工具栏共用 src/theme.h 的调色板，正文为深灰紫，时间为柔和灰紫，工具栏选中态为淡紫。关闭透明效果或材质失败时使用同色系不透明底。

状态灯、胶囊和独立提醒共享固定的浅色底/深色字配对，不采样桌面：完成 #DCEFE9/#376F63、工作中 #DEE9FA/#4C6594、等待回答 #FAE8D3/#8E5B34、错误 #F6DEE8/#924A64、中断 #E8E0F2/#725A8B、未知 #E7E7E9/#656570、离线 #E2E6EB/#596779。七组颜色的文字对比度均达到 4.5:1。左侧实心圆保持 7.5 DIP 半径，不叠加光圈，圆心改为距左侧 18 DIP，标题起点 34 DIP，增加边缘和符号与文字之间的留白。

状态胶囊使用浅色实心底与深色文字，字形按实际 ink bounds 横纵居中。会话标题和时间也按实际字形范围在整行中垂直居中，覆盖中文字体回退、英文下伸部和省略号，不再依赖固定的顶部偏移。几何生成失败时回退到字体度量居中。

面板采用系统 Desktop Acrylic、圆角及 DirectWrite。针对背景亚克力在非激活时回退成实色的行为，保持浮层 non-client 活跃外观，而不通过激活窗口来换取材质；展示及主题/合成变化后重新应用材质。初始化失败会使用实色底。透明效果关闭、高对比、节能等系统回退仍遵循系统策略。无需 WinUI 3、Windows App SDK、WebView2、Python、Node 或额外 VC 运行库。目标最低系统 Windows 11 26200.8875，x64。窗口使用 Per-Monitor V2 DPI 感知，显示器变化时重新布局并重建对应渲染目标。系统 DPI、宠物大小和面板缩放分别处理，提醒的窗口宽度及徽章只跟随系统 DPI；提醒文字使用与主会话行相同的最终字号，随面板缩放同步，窗口高度随一或两行文字调整。

面板优先创建 Direct2D 硬件渲染目标，硬件不可用时回退软件，并缓存文字排版、测量和状态字形，避免每帧重复创建。宠物 GIF 仍使用 GDI+ 在 CPU 上绘制，但复用位图/DC，保留素材原始帧间隔。本机三类浮层实测均为硬件渲染，120 Hz 垂直同步下 UI 平均帧间隔约 8.33 ms。

## 状态的准确范围

在官方版 3.16.3 本机验证：应用进程检测成功，只读列出 5 个已有会话，无需重启 ZCode。

每两秒只读查询 `~/.zcode/v2/tasks-index.sqlite`，包含 WAL 中已提交记录；当前回合的日志提供活动证据。完成气泡直接使用索引中的会话名称，不再额外读取最终回复作为完成气泡内容。不读取凭据。

当前日期官方日志中的 `cua-pip-session` 回合事件作为活动证据。忽略早于当前 ZCode 主进程启动的事件，按 turnId 排除旧回合结束事件。不按运行时长自动降级状态，长任务会持续工作中直到明确结束；程序退出清除运行态。状态栏明确区分日志观察与上次持久化结果。

行末是当前状态已持续多久：`10s`、`2m`、`3h`、`1d`。有明确日志起点时从状态事件算起，完成后从完成时刻继续增长，不再显示任务总用时。没有真实起点的历史/未知/离线状态，从首次观察算起，并加 `≥` 表示至少持续了这么久。标题刷新不会重置计时，新回合或状态变化才重置。已知会话状态变化时，左侧徽章与右侧状态标签同步上抬最多 2.6 DIP 后回落；标题、时间及行布局保持固定。首次观察、同状态刷新及隐藏期间的变化不触发轻跳。后台状态仍每两秒采样。工作中转圈、标题扫光、状态轻跳及浮层进退场共用高精度时钟，由宠物所在显示器的垂直同步信号驱动；120 Hz 下约每 8.33 ms 一帧，切换显示器后自动跟随。UI 待处理帧最多一条，繁忙时跳过旧帧；静态时停止高频绘制，只每 100 ms 检查年龄文本是否变化。时长始终按实际时间差计算，不靠计时器次数累加，也不承诺主线程阻塞时不会跳过中间数字。

这不是官方公开订阅接口：日志缺失、轮转、升级改变格式，或超过读取的末尾 4 MiB 时，运行态可能不可见。已覆盖 AskUserQuestion 的等待回答：只读读取匹配当前活动回合的运行中工具记录，显示等待回答状态、期待动画和独立橙色提醒气泡；有内容时显示问题短摘录。同一 interactionId 只提示一次，开始观察时已有的有效等待也会提示；回答后气泡作为通知记录保留，直到用户手动关闭。回答后恢复工作的状态年龄从工具结束时算起。其他工具的权限审批、子代理状态仍缺少可靠来源，不能将任意运行中的工具猜成待审批。仅支持当前 Windows 用户的本地默认数据目录；远端会话没有本地证据时只显示历史结果。

动画：空闲 idle，悬停/等待回答 waiting，工作中 working，错误或中断/拖动 paused。每个新完成事件立即进入 success 动作队列，每次约 4 秒，多个完成依次播放；完成动作优先于等待和工作，播完后恢复当前状态。GIF 保持原始帧间隔。

新回合完成后，每个 session 显示独立的原生亚克力气泡，不再逐条排队等待关闭。完成气泡只展示当前会话名称与“已完成”，不显示初始用户描述或回复摘录；已有气泡跟随会话重命名。各气泡可分别关闭、悬停和点击正文导航。相同 workspace/session 开始明确的新一轮时，旧完成气泡自动退场；其他会话、重命名、离线或读取失败不会误清理，没有新一轮则保留到手动关闭。等待气泡继续保留到手动关闭，可显示问题。历史完成不在启动时补弹，退出后不保存气泡。

所有气泡与 Sessions 面板物理宽度相同，统一跟随系统 DPI、面板缩放及屏幕限宽。内容共用会话行的 34 DIP 标题起点、18 DIP 徽章中心、10 DIP 右边距；完成气泡与单行 session 等高，双行等待气泡仅增加一个行距，徽章保留原有实际大小。气泡间及气泡与 Sessions 之间的可见间距统一为 8 个系统 DIP，不重复叠加关闭钮或动画余量。左上角关闭钮维持外伸布局，屏幕边缘及工具栏避让仍计入按钮占用，整组跟随宠物移动。表面沿用原生圆角、亚克力和系统投影；220 ms 进场、110 ms 退场以及 hover/press 仍由显示器垂直同步驱动。

手动关闭或新一轮自动清理后，剩余气泡使用 200 ms CSS ease-out 同步平滑补位，复用屏幕刷新率时钟。连续关闭会从当前显示位置重新定向，正在补位的气泡被关闭时从当前位置退场，关闭钮逐帧跟随；同目标刷新不重启动画，结束后停止请求帧。最终间距保持 8 DIP；拖动宠物时直接跟随。关闭钮沿用原有大小和左上角位置，hover 提亮、press 压暗，复用交互动效与屏幕刷新率时钟；点中后带按下反馈随气泡退场。会话与气泡里的勾统一使用连续路径及圆角连接，避免拐角缺口；加载弧线和感叹号也采用圆头及稍饱满的线宽/圆点，状态底圆和布局不变。

## 亚克力文字实验

默认 DirectWrite 灰度 AA，直接绘制在透明亚克力表面。

可切换实验模式：`IDWriteGlyphRunAnalysis::CreateAlphaTexture(DWRITE_TEXTURE_CLEARTYPE_3x1)` 提取真实三通道覆盖率，按显示器 RGB/BGR 排列处理，再根据参考背景编码为普通预乘 BGRA。可选择 50%、75%、100% 子像素强度。

统一 alpha 为覆盖率最大值，颜色为 `coverage[k]*text[k] + (alpha-coverage[k])*referenceBackground[k]`。输出满足预乘约束。数学测试验证参考背景一致时的 source-over 等价性。

实验使用参考浅色背景，不采样桌面。因此实际背景偏离参考色会产生误差；尚未模拟原生 ClearType 全套 gamma/contrast 校准。背景快速变化、HDR、旋转屏幕及混合 DPI 仍待进一步视觉验收，不能宣称与原生不透明 ClearType 完全等价。有色边时可降低强度或切回灰度。系统会自行决定透明效果关闭等情况下的材质回退。

## 构建

需要 Visual Studio C++ 桌面工作负载、Windows SDK 和 CMake（仅构建机需要）。本机使用 VS 2026、SDK 10.0.26100，Release `/MT`。

```powershell
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

`ZCodePet.exe --probe` 只读检查观察器、浮层布局、实际渲染后端及帧时钟，并写 EXE 旁边的 `probe.txt`，不输出会话标题或内容。可查看 displayHz、vblankClock、visualFrameAverageMs、panelCenterOffset 和各 renderer 字段。`--self-test` 验证回合顺序和覆盖率数学；`--panel` 启动时展开面板。`--quit` 正常退出已运行的桌宠。

GPU 对照诊断：`scripts/profile-gpu.ps1 -Exe .\build\Release\ZCodePet.exe -OutputDirectory .\build\gpu-profile`。脚本依次重启到本地固定场景，采集 Windows GPU 引擎原始计数器、进程 CPU/显存及绘制次数，写入 summary.json/csv、engine-samples.csv，最后恢复正常面板；当前脚本需要 NVIDIA 的 nvidia-smi 记录整卡快照。可用 `-RestoreExe` 指定恢复运行的便携版，`-Scenes` 限定场景、`-Samples` 调整每场景采样数。显式 `--gpu-profile=<scene>` 支持 pet、pet-frozen、static、running，以及 running 后追加 no-shimmer/no-spinner/no-acrylic/frozen-gif 的组合，仅用于诊断；不读写 ZCode、不修改用户设置。

v24 加入背景材质选项及静态纹理/扫光字形遮罩缓存，保留全部动效与显示器刷新率。背景、普通文字、分割线、状态胶囊等视觉内容不变时直接复用纹理，年龄/状态/名称/布局/交互变化才更新；纹理保留 alpha，不把桌面背景烘焙进截图。缓存失败自动回到原绘制，支持原有实验文字。新增 `--panel-scene-test` 检查缓存失效条件，已加入 CTest。`--probe` 增加 panelCacheBuilds/Hits/Fallbacks、backdropMode/Type 及 panelDrawResult/Errors。诊断支持 running-mica、running-solid、no-cache/no-mask（禁用两种缓存），可与 no-shimmer/no-spinner 组合；固定场景不会保存材质偏好。

同机 v24 最后复测（每场景 6 个约一秒样本，三行工作、120 Hz）：原路径两轮 2.70% / 2.82%，新路径两轮 1.71% / 1.68%，Mica 1.79%；均无 EndDraw 错误，静态纹理约每秒重建一次、其余约 119 帧命中缓存。专用显存约从 16.1 MiB 增至 17.1 MiB。不同轮次有桌面活动导致的波动，不据此声称材质节省某个固定百分比。另一次 120 Hz 关闭扫光/转圈的对照仍约 1.07%，说明持续整窗提交存在明显基线成本；只减小重绘区域的实验没有明显收益，未启用该路径。若继续降低这部分成本，需要拆分合成层和改变 HWND 逐帧提交方式，单纯切换 Mica 无法保证解决。Mica 只取壁纸、Acrylic 实时取后方内容，系统合成成本仍受桌面活动影响。

v25 已将面板基底和运行态动画改为系统 Windows Composition 合成层（系统自带，无需 Windows App SDK/WinUI 运行库），二者共用一套 D3D/D2D 设备，正常路径不再创建旧 HWND 渲染目标。保留转圈、扫光和显示器刷新率。同机同材质三行工作场景：旧路径应用 3D 为 2.680%，最终路径两轮为 0.046% / 0.041%，约下降 98%；面板绘制从 120 次/秒降至约 1 次/秒（年龄更新），稳定态 UI 高频帧为 0。专用显存约 18.9 MiB，旧路径约 17.1 MiB。新路径 DWM 在不同样本约 3.19%～4.39%，它反映整个桌面，不能全部归给桌宠；此处不推算整卡功耗，也不宣称合成器播放动画零成本。不同测量轮次的 GPU 时钟/桌面活动会变化，CSV 保留原始数据供对照。

转圈复用一张小尺寸纹理并由合成器旋转，扫光使用静态字形遮罩及移动渐变；全部可见工作行共用两个循环时钟。年龄更新、hover/press、轻跳和宽度变化不会重启循环时钟；隐藏/移除后解绑动画，无工作行时停止循环。普通面板、提醒不因相同后台快照反复重绘。材质选项、文字实验、状态轻跳、浮层进退场及导航保持原行为。组合器/设备初始化或更新失败自动回到 v24 绘制路径，诊断会显示失败 HRESULT；新路径不是通过降低刷新率、禁用光效或冻结 GIF 降耗。

诊断 `running-legacy` 强制 v24 路径作配对对照，可与其他 GPU 场景后缀组合。`--probe` 的 compositionReady/Result/Failures 检查后端及错误，compositionUploads/Starts/Updates/Rows 检查纹理更新、两个循环时钟和行生命周期；它们不是合成器实际显示帧数。高频 UI 线程休眠时 visualFramesNeeded=0，但系统动画仍随显示器刷新率播放。新增 `--composition-test`，验证重复更新不重传纹理/重启时钟、重命名/缩放/轻跳、挂起/恢复、移除行及线程资源释放，已加入 CTest；不支持合成器的无桌面环境验证安全回退。

2026-10-29 本机 RTX 5080 / 120 Hz、三行运行中场景实测：修复重复绘制前，桌宠自身 3D 引擎约 2.98–3.01%；修复后两轮约 2.67–2.70%，面板绘制稳定 120 次/秒。关闭标题扫光的对照约 2.02%，静态面板约 0.009%，仅 GIF 的对照接近 0%。主要成本是运行中面板持续整面重绘，标题扫光有额外成本。移除转圈或亚克力的对照没有显示显著的应用自身 3D 降幅；系统 DWM 的亚克力合成成本不能据此排除。GIF 按原素材约 31 次/秒上传，仍包含 CPU 绘制与系统合成开销。测量时 Sunshine 持续编码、其他桌面程序保持运行，数据用于本机相对对照，不代表通用性能或整卡功耗归因。正常模式保留全部视觉效果及刷新率，只去掉 100 ms 定时器和两秒快照重复插入的动画面板重绘。

`--demo --preview --panel` 使用本地演示事件：8 秒首个会话完成、10 秒第二个会话完成，另一个会话持续工作；12 秒新增等待提醒，14 秒重命名首个会话，18 秒首个会话进入新一轮并清理旧完成提醒。可验证多气泡、完成动画、名称同步、单独关闭及新轮清理，不给 ZCode 发任务或写入状态。正式运行不加 demo/preview。
